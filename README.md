# CytoLex

CytoLex validates **ISCN cytogenomic nomenclature** strings: karyotypes, FISH (`ish`, `nuc ish`), microarray (`arr`) and more.

- **Version-aware.** Results are given per ISCN edition. ISCN 2016 comes first; 2020 and 2024 follow later, because editions are not backward compatible.
- **Cited.** Every diagnostic points to the book, e.g. `ISCN 2016 §9.2.17.1, p.75, ¶1`.
- **Helpful.** It suggests deterministic fixes where one exists, or explains the problem otherwise.

> **Status:** planning/foundation phase. The repo tooling (`tools/`) is set up, `kb extract` works and its output has been reviewed against the book ([`docs/extraction-review-2016.md`](docs/extraction-review-2016.md)), the KB file format is fixed by JSON Schemas ([`kb/README.md`](kb/README.md)), `kb build` checks the KB and compiles it to SQLite + JSON, and `kb bands` generates the band data, checked against the book's idiograms (`kb ideograms`). The .NET solution (core library, desktop app, tests) is scaffolded and builds; the core splits strings into technique segments, detects their type and infers the sample context (T-026; breakage and meiotic strings such as `chtg(4)(q25)` or `MI,23,XY` are detected by their leading symbol and reported as not implemented, T-018, as are region-specific assay (`rsa`) and sequence-based (`seq`) results, whose KB rules were added in T-019), parses karyotype segments into a lossless syntax tree with error recovery (T-027), and validates per ISCN edition through the rule engine (`Validator`, T-028: KB-cited diagnostics, all-editions results with 2020/2024 not implemented) and binds each tree to a semantic model of meaning nodes with KB refs (T-065); rule checks exist for the ch. 2–3 general and band rules (chromosome identifiers, band format and existence, symbol spacing; T-029) and for chromosome counts, ploidy, the sex chromosome field and the order of abnormalities (T-030), and for structural rearrangements: chromosome and breakpoint order, breakpoint groups, the detailed system and derivatives (T-031), and the other ch. 9 symbols: del/dup/i/fis/fra forms, p10/q10 and whole-arm rearrangements, rob/dic, hsr, markers, unidentified rings, double minutes and copy numbers (T-068), and neoplastic clones: idem/sl/sdl references (resolved to the clone they refer to and checked against its count), composite karyotypes (`[cpN]`, per-abnormality cell counts), clone size, related and unrelated clone order, normal and constitutional-only lines last, constitutional clone order and jumping translocations (T-032). Microarray results (`arr`, ch. 14) are parsed and checked too (T-034): genome build, nucleotide format, normal results, order of aberrations, regions and pter→qter, copy numbers, proportions, inheritance and zygosity, `cx`/`cth`, the order of combined karyotype/FISH/array results, and whether the positions lie in the named bands of the stated build (T-088, a warning that says when they fit the other build). In situ hybridization results (`ish`, `nuc ish`, `fib ish`, `rev ish`, `ish cgh`, ch. 13) are parsed and checked too (T-033): probe names, locus lists and status, signal counts and shared counts, signal positions (`con`/`sep`), qualifiers (`amp`/`dim`/`enh`), cell counts and cell lines, normal and abnormal chromosomes, inversions, partial paints, the short and detailed nuc ish forms, and the period before an in situ result; the order of loci along a chromosome is not checked yet (it needs probe positions). Diagnostics carry fixes (T-035): deterministic level-1 edits with a before/after preview (every KB `corrected` form is reproduced exactly), or a level-3 explanation with book citations when no single fix exists; `Fixer` applies one fix or all non-overlapping ones. The desktop app does the single-string check (T-036): it shows the detected segment types, the context and the verdict, highlights the input (wrong ranges underlined, missing text as an insertion marker with grey expected text, extra text struck through) and lists the diagnostics with their citations and fixes. An edition selector (T-037) validates in one ISCN edition or in all of them; each edition is a chip with its verdict (`2016 ✗ 2 errors`, `2020 n/a`), and the editor highlights the selected chip's edition. The results of the selected edition are full-width view tabs (T-098): Diagnostics (default) | Abnormalities | Translation | CytoGPS; the chosen view stays while typing or switching editions. Results also list each karyotype's abnormalities by cell line (T-069: kind, chromosomes, breakpoints, short form such as `t(9;22)`, derivative parts, flags, diagnostics), which the desktop app shows in an "Abnormalities" panel linked to the input; microarray results are listed there too, one group per `arr` segment with each result's copy number as written, bands, positions and build, proportion, zygosity and origin (T-072); in situ results are listed by cell line of each `ish`/`nuc ish`/`fib ish`/`rev ish`/`cgh` segment, each result with its loci (status, signal counts, `con`/`sep`), cells and, for normal results (the normal-chromosome form, `subtel(41×2)`, nuc ish loci all ×2), a muted "normal" tag (T-092). A clone written with `idem`/`sl`/`sdl` lists the changes it inherits from the clone it refers to (×n for a polyploid clone, a `–inv(6)` or `+3` removing the inherited `inv(6)` or `–3`) and its written-out full form, e.g. `46,XX,t(9;22)(q34;q11.2)[7]/43,sl,-7,-9,-15[11]` → `43,XX,-7,-9,t(9;22)(q34;q11.2),-15[11]`; in the desktop panel the reference row expands to the inherited changes ("from line 1", click selects the source) and the cell-line header shows the full form with Copy (T-070). Each rearrangement also gets its band composition, computed from the short system (T-066): the list and the panel show it in the detailed system, e.g. `der(9)t(9;22)(q34;q11.2)` → `der(9)(9pter→9q34::22q11.2→22qter)` (equal to the book on 87 of its 89 example pairs printed in both systems). Batch validation (T-038): the desktop "Batch" tab loads a text, CSV or TSV file, validates every string in parallel (1,000+ strings in about a second), shows a summary per edition and a filterable table, opens a row in the single-string check, and exports a CSV summary (one row per string and edition) or the full reports as JSON. Both exports read back. Reusable sample files generated from the KB examples are in `tests/data/batch/` (`kb samples`). A rule browser (T-039): the desktop "Rules" tab searches the KB rules of an edition (full-text over IDs, titles, statements, example strings such as `t(9;22)` and source quotes, read from `build/kb.sqlite`), filters by book section and shows a rule's statement, citations, scope, fix hint, review state, related rules, valid/invalid examples (each can be opened in the single-string check) and quotes; quotes are optional. Clicking a diagnostic's rule ID opens its rule. Fix UI (T-040): every level-1 fix shows a before/after diff (removed text red and struck through, added text green) with an **Apply** button that changes the input and re-validates (Ctrl+Z undoes it); "Fix all (N)" previews one round of every non-overlapping fix and comes back while fixable findings remain. Fixes are computed from the string, so they work on any string, not only book examples; a test checks that every whole-string invalid KB example whose findings have certain fixes ends valid (`build/review/fix-coverage.md`). Stray spaces (`47,XY, +21`, `46,X Y`) and wrong letter case (`46,xy`, `Del(5)`, `T(9;22)`) are reported with a one-click fix (T-074); a wrong-case symbol is still read as the listed one, so it gets no follow-on errors. The core can also correct such faults automatically on request (T-096, autocorrection): the KB flags the rules whose fixes keep the meaning (stray spaces, letter case, spaces in a band designation), the validator applies them, re-validates and keeps the original next to the corrected string and the list of corrections; a string that is valid only after that gets its own verdict, "valid after autocorrection", and the batch exports carry the original, the corrected string and the corrections. The desktop app has an "Autocorrect" checkbox (on by default) in the single-string check and the Batch tab: the editor keeps the typed text with the remaining findings on it and the corrected spots softly underlined, a "Corrected" line shows the corrected string with one note per correction (Copy, Use corrected), and the Batch tab adds a Corrected column and an "Autocorrected" filter; the rule browser marks rules with `fix.auto` (T-097). An adapter runs a locally compiled CytoGPS on a batch and normalizes its results (verdict, messages, Loss–Gain–Fusion per band and clone) (T-049; optional setup, see [CytoGPS (optional)](#cytogps-optional)), and a comparison engine sets CytoLex's ISCN 2016 verdicts against CytoGPS's on a batch (T-051): a 2×2 agreement matrix, strings CytoGPS can't read (ish, arr, the detailed system, `fra`/`upd`/`rec`/…) kept out of it, the disagreements with triage labels from a committed file (`tests/data/comparison/`; first run: 459 strings compared, 84.3 % agreement, all 72 disagreements triaged, none a CytoLex bug), and confirmed cases exported as draft KB examples; the report is written to `build/review/comparison/` by an opt-in test. The desktop single-string check has an optional CytoGPS view tab (T-081): "Check with CytoGPS" (or automatically after a typing pause) runs the local build in the background and shows its verdict, status, messages, repaired string, the string as sent and whether it agrees with CytoLex's ISCN 2016 verdict (notation CytoGPS can't read is marked "not supported", not counted as a disagreement); without a setup the tab only shows why, and CytoLex works the same either way. The Batch tab compares a loaded batch with CytoGPS too (T-052): "Compare with CytoGPS" runs both in ISCN 2016 (with Autocorrect ticked, a string CytoLex finds valid after autocorrection, such as `46,xy` or `47,XY, +21`, counts as valid for CytoLex; CytoGPS always gets the string as written; the single-string CytoGPS badge follows its Autocorrect checkbox the same way) and shows the agreement matrix, an Agreement and a Triage column, filters for disagreements and untriaged disagreements, and for the selected row CytoLex's and CytoGPS's verdicts side by side with a triage editor (label, confirmed, note); the triage file (by default the committed `tests/data/comparison/cytogps-2016-triage.yaml`, header comments kept) is saved as YAML, stale entries can be removed, and the report files (Markdown, CSV, triage draft, KB-example draft) can be exported to a folder. Without a setup, or when CytoGPS fails, the comparison says why and the batch results stay as they are. The core library also renders a literal plain-language translation on request (T-058): a summary line and one sentence per part (e.g. `46,XX,del(5)(q13q33)` → "46 chromosomes; sex chromosomes XX; 1 abnormality." + "Interstitial deletion of chromosome 5: the segment between 5q13 and 5q33 is lost."), with links to the KB entries, both readings where the sample context changes the meaning, parts with syntax errors marked "not translated", and optional approximate GRCh37/38 coordinates; it reproduces all 398 expected translations of the golden file exactly (draft wording until reviewed, T-082). The desktop app shows it in a "Translation" view tab (T-059) with the partial-translation banner, a draft-wording note, the summary and one card per part; hovering a card marks its span in the input and hovering the input marks the part; rule and symbol links open the rule browser, which now lists the KB's symbols and banding codes too; a "Genomic coordinates" toggle (off by default) shows approximate band coordinates and segment sizes in GRCh38 or GRCh37. For an unknown symbol or band name the check also offers 1–3 "did you mean" options (T-041: `dl` → `del`, `trans` → `t`, `9q35` → `9q34`, an arr band → the band that holds its position), each with a diff and Apply; they are never applied automatically, by "Fix all" or by autocorrection. Underlined homologues (T-042) are typed as U+0332 after each underlined character (`der(1̲)t(1̲;3)`), the form the book's examples use in the KB; they are validated like plain chromosome numbers, and in the desktop editor Ctrl+U (or "Underline homologue" in the context menu) underlines or un-underlines the selection or the number at the caret. A test corpus of realistic synthetic strings (T-062: 213 entries over karyotype, arr, ish, nuc ish, combined and robustness inputs, each with its KB rules and expected result per edition) runs in `dotnet test`, together with a mutation generator that turns trusted valid entries into invalid ones (14 operators, each grounded in a book example of its rule; 916 mutants, each must report its rule). Progress is tracked in [`TASKS.md`](TASKS.md).

## Architecture (planned)
- **Core library:** UI-free ISCN parsing and validation, driven by a knowledge base (KB) of cited rules.
- **Desktop app:** the pilot UI. Single-string check, batch validation, rule browser, fix view.
- **Web service:** later, reusing the core library.

The app stack is C# on .NET 10 LTS: a core library with a hand-written parser, an Avalonia + AvaloniaEdit desktop app, xUnit v3 tests, and ASP.NET Core for the web service later (decision T-020). The projects are scaffolded (T-024); see [Getting started (app)](#getting-started-app). The pilot validator covers karyotypes from ISCN ch. 2–9 (constitutional and acquired, numerical and structural, mos/chi), using only the string as input. Neoplastic clones, microarray and FISH come later, in that order (decision T-021). A string is valid when it has no errors; warnings and info notes are listed but don't affect validity (decision T-022). The core library's design (data model, version profiles, result/diagnostic API, fix model) is in [`docs/design/core.md`](docs/design/core.md) (T-023). All decisions and their rationale are in [`docs/decisions.md`](docs/decisions.md).

## Getting started (tooling)
Requirements: Windows, macOS or Linux with **Python 3.14** and **[uv](https://docs.astral.sh/uv/)**. Install uv with `py -m pip install --user uv` or `winget install astral-sh.uv`. If `uv` isn't on PATH, use `py -m uv …` instead.

1. Point the tools at your copy of the ISCN book. The PDF is copyrighted and is never committed.
   ```sh
   cp config/local.example.yaml config/local.yaml   # then edit iscn_pdf paths
   ```
   Or set an environment variable instead, e.g. `CYTOLEX_ISCN_PDF_2016=C:/books/ISCN_2016.pdf`.
2. Install the environment:
   ```sh
   uv sync --directory tools
   ```
3. Run the KB CLI from the repo root. All subcommands work.
   ```sh
   uv run --directory tools kb --help
   uv run --directory tools kb extract --version 2016   # PDF → kb/source-text/2016/ (--pdf, --out to override)
   uv run --directory tools kb tables --version 2016    # table images for review → build/review/tables/2016/
   uv run --directory tools kb check                    # rule/quote/vocab YAML vs kb/schema/ (or: kb check <files/dirs>)
   uv run --directory tools kb build                    # check KB → build/kb.sqlite, kb.json, kb-runtime.json, review/kb-review.md
   uv run --directory tools kb ideograms --version 2016 # book idiogram labels (PDF) → kb/bands/2016/ideograms.yaml
   uv run --directory tools kb bands                    # NCBI GDP + UCSC cytoBand + book → kb/bands/2016/bands.yaml
   uv run --directory tools kb samples                  # KB examples (build/kb.json) → tests/data/batch/2016/ sample files
   ```

## Getting started (app)
Requirements: the **.NET 10 SDK** (any 10.0.x; `global.json` pins the major version and opts `dotnet test` into Microsoft.Testing.Platform). Run everything from the repo root.

1. Build the KB bundle first. `CytoLex.Core` embeds the lean runtime bundle `build/kb-runtime.json` (the test project also embeds the full `build/kb.json`), and the desktop app copies `build/kb.sqlite` for its rule browser; `dotnet build` stops with "KB bundle not found …" or "KB database not found … Run 'uv run --directory tools kb build'" if one is missing:
   ```sh
   uv run --directory tools kb build
   ```
2. Build, test and run:
   ```sh
   dotnet build                                   # whole solution (CytoLex.slnx); warnings are errors
   dotnet test                                    # all tests, incl. one case per KB example (skipped until the validator exists);
                                                  # also writes build/review/rule-coverage.md and build/review/fix-coverage.md
   dotnet test --filter-method "CytoLex.Core.Tests.EmbeddedBundleTests.EmbeddedBundle_IsPresentAndParses"   # single test
   dotnet test --project tests/CytoLex.Desktop.Tests   # one test project (desktop highlight mapping + view models)
   dotnet run --project src/CytoLex.Desktop       # desktop app
   dotnet format --verify-no-changes              # lint (code style); `dotnet format` fixes
   ```
   `--filter-method` accepts `*` at either end (`"*IsPresentAndParses"`); `--filter-class` selects a whole test class.
3. NuGet versions live in `Directory.Packages.props` (Central Package Management); projects reference packages without a version.

### CytoGPS (optional)
The CytoGPS adapter (`src/CytoLex.External/`, T-049) runs a **local** build of [CytoGPS](https://github.com/i2-wustl/CytoGPS) only, with synthetic or ISCN-book strings (decision T-048; findings in [`docs/research/cytogps.md`](docs/research/cytogps.md)). Without it, everything else works; its integration test skips with "CytoGPS not configured: …", and the desktop app's CytoGPS tab (T-081, same setup) and the Batch tab's comparison (T-052) show that reason instead of a result.
1. Get an unpacked copy of the CytoGPS repo (not committed here), a JDK (e.g. Temurin 21, portable zip) and `javax.json-1.1.4.jar` from Maven Central (`https://repo1.maven.org/maven2/org/glassfish/javax.json/1.1.4/`; its SHA-1 is checked).
2. Fill in the `cytogps` section of `config/local.yaml` (template in `config/local.example.yaml`; env vars `CYTOLEX_CYTOGPS_<KEY>` override it).
3. Run the integration test; the first run compiles CytoGPS into `build/cache/cytogps/` (recompiled only when the sources change):
   ```sh
   dotnet test --project tests/CytoLex.External.Tests --filter-class "CytoLex.External.Tests.CytoGpsIntegrationTests"
   ```
   Results are cached in memory; `disk_cache: true` also caches them under `build/cache/cytogps/results/` (synthetic/book strings only).
4. Write the comparison report (T-051) for the KB sample batch into `build/review/comparison/` (`cytogps-2016.md`, `.csv`, a triage draft and a KB-example draft; triage workflow in [`tests/data/comparison/README.md`](tests/data/comparison/README.md)):
   ```sh
   dotnet test --project tests/CytoLex.External.Tests --filter-class "CytoLex.External.Tests.CytoGpsComparisonReportTests"
   ```

Typical flow:
1. **One-time setup:** `uv sync --directory tools`, fill in `config/local.yaml`, run `kb extract`. (`kb/bands/` is committed, so `kb bands` isn't needed after a clone.)
2. **KB work (T-008 onwards):** if the task's tables still need a person sign-off, do that first and run `kb extract`; then write or edit rules and vocab files (format: [`kb/README.md`](kb/README.md)), run `kb check` while editing, then `kb build` until it passes, then `kb samples` if examples changed.
3. **App work (T-024 onwards):** run `kb build` first, then `dotnet build`/`dotnet test`, so the app and its tests use the current KB.

## Source-text chunks (`kb extract`)
`kb extract` turns the ISCN PDF into one Markdown file per numbered section, plus `manifest.yaml`. It is deterministic and uses no AI: re-running gives byte-identical output.
- **Files:** `kb/source-text/2016/ch09/09.02.17.01-reciprocal-translocations.md`. Numbers are zero-padded so files sort in book order. A section over the 4,000-token cap is split into `-p1`, `-p2`…
- **Front matter:** section, title, book and PDF page ranges, and the citation labels in the file, with their pages.
- **Citation labels:** `[¶n p.75]` marks a prose paragraph and `[En p.75]` an example block (with its explanation quoted below it). Both restart at every numbered heading, so a citation reads `ISCN 2016 §9.2.17.1, p.75, ¶1` or `… ¶2, ex. E3`. Figures and tables are labelled by their own number (`[Fig. 7 p.39]`, `[Table 1 p.12]`) and don't count as paragraphs.
- **Tables:** tables listed in `tools/src/cytolex_tools/extract/tables/<version>.yaml` (page area, column positions, review status) become Markdown tables.
- **Layout marks:** an underlined character (used to tell homologues apart) is followed by U+0332, e.g. `der(1̲)`; front matter `changed` lists the labels beside a margin change bar (changes since the previous edition) and `underlined` the labels with underlining.
- **Faithful text:**
  - Symbols that the PDF stores under other characters are restored by font (`]` → `→`, `~` → `×`, `!4n1` → `<4n>`, …).
  - Invisible zero-width spaces are dropped.
  - Example strings are otherwise verbatim. The manifest lists every glyph mapping and anything it couldn't map.
- **Exit code 1** if a TOC section isn't found on its TOC page, or a configured table region is empty.
- **Known limits:** what the text layer can't carry (drawn diagrams, shading, bold/italic, the ploidy table's indentation) is listed per section in [`docs/extraction-review-2016.md`](docs/extraction-review-2016.md); rules citing those sections get `needs_review`.

## Development
App (.NET), from the repo root: `dotnet build`, `dotnet test` (single test: `dotnet test --filter-method "<Namespace.Class.Method>"`), `dotnet format --verify-no-changes`; see [Getting started (app)](#getting-started-app).

Tooling (Python):
```sh
uv run --directory tools pytest                                                   # all tests
uv run --directory tools pytest tests/test_cli.py::test_help_lists_subcommands   # single test
uv run --directory tools ruff check .                                             # lint
uv run --directory tools ruff format .                                            # format
```

You can also `cd tools` and drop `--directory tools`.

**Line endings:** every file is LF on every OS (`.gitattributes`: `* text=auto eol=lf`, T-055), so generated committed files (`kb/bands/…`) match their generators byte for byte. If a working copy from before T-055 still has CRLF files (`git ls-files --eol | grep w/crlf`), convert it once on a clean tree: `git rm -r --cached -q . && git reset --hard`.
